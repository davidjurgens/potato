# Release Notes: v2.11.1 — Debug Without --host, Image Classifiers and Prelabels After a Restart

This release restores `--debug` on the default bind, which 2.8.2 through
2.11.0 refused. It also adds image classifiers to model training, lets a run
prelabel items nobody has labelled yet, and fixes prelabels that were lost on
every restart.

```bash
pip install --upgrade potato-annotation
```

## `--debug` starts again without `--host`

Since 2.8.2, a debug server on the default `0.0.0.0` bind refused to start
unless `--host 127.0.0.1` was given, so the documented command
`potato start config.yaml --debug` failed. In 2.11.1 it starts on any bind,
and other machines on the network can reach it.

In debug mode:

- **The login page stays unless you add `--debug-phase`.** With
  `--debug-phase`, every visitor is signed in as the shared `debug_user` and
  sent to that phase, so anyone who can reach the server annotates under that
  account. Do not use it for a real study. The `D002` preflight check still
  blocks `debug: true` on `potato deploy`.
- **Admin pages open without a key only for requests from the machine the
  server runs on**: a loopback address with no `X-Forwarded-For`,
  `X-Real-IP` or `Forwarded` header. A request from another machine, or one
  that arrives through a proxy, still needs the admin key. This holds on a
  `127.0.0.1` bind too, where 2.11.0 let every request through: a proxy or
  tunnel on the same machine forwards other machines' requests to
  `127.0.0.1`.
- **The media endpoints answer without a login only for requests from this
  machine.** The waveform, video metadata and audio proxy endpoints fetch a
  URL the caller names, and under debug they answered anyone.
- **The Werkzeug interactive debugger is served only on a `127.0.0.1`
  bind**, because it runs code typed into the browser.

`POTATO_ALLOW_REMOTE_DEBUG` is no longer read. If you added
`--host 127.0.0.1` to your debug commands for 2.8.2 through 2.11.0, it still
works and still gives you the interactive debugger.

## Image classification

- **Model training trains image classifiers.** A radio or multiselect scheme
  whose items name image files is treated as an image corpus, and the
  `sklearn-text` trainer fits it on CLIP embeddings unless the run names a
  vectorizer. It used to fit TF-IDF on the file paths. `/media/...`
  references resolve against `media_directory`. Rows whose image is remote
  or missing are left out of training with a warning instead of becoming
  blank embeddings, and get no prediction. A text item that also carries a
  remote `image_url` is still a text item. The saved model no longer
  contains the CLIP weights, which made every `model.pkl` about 600 MB.
- **Image active learning works as documented.** `vectorizer: {name: image}`
  (or `clip`) builds the CLIP vectorizer, and every scheme, radio and
  multiselect included, gets the item's image. `image` was not a name the
  manager could build, so such a study was ranked by TF-IDF over file paths.
  `/media/...` references are read from `media_directory`, and
  `image_root` defaults to `task_dir`. If more than half of the training
  images cannot be read, the retrain fails with an error naming some of them
  and the queue keeps its previous order.
- **The labeling engine distils image classifiers.** On an image study
  (`labeling_engine.distill.modality`, default `auto`, with `image_field`)
  the distilled tier is a CLIP-embedding classifier, and it abstains on
  images it cannot read. A new tier is trained when the accepted labels have
  doubled (`distill.every`) since the last one.

## Prelabels for unlabelled items

`model_training.writeback.include_unlabeled: true` makes a run predict on the
items nobody has labelled yet and prelabel them under the usual write-back
checks. Before this, a run predicted only on its held-out val and test items,
which are already labelled, so write-back never reached the items a prelabel
is for. The default is `false`.

```yaml
model_training:
  writeback:
    schemas: [sentiment]
    include_unlabeled: true
    min_confidence: 0.7
```

Prelabels now show on the annotation page as a pre-filled answer once
`writeback.schemas` is set. They used to show only when a `pre_annotation`
block was also enabled with the same `field`.

When a run trains on an item, a prelabel an earlier run left on that item is
taken down, and it stays down after a restart. Withdrawing a run's
predictions (`DELETE /admin/training/api/runs/<run_id>/predictions`) now takes
its prelabels off the items at once; they used to stay until the next
restart.

The new [Model Training](../ai-intelligence/model_training.md) page covers
training runs, write-back and the review queue.

## Bug fixes

- **Prelabels did not survive a restart.** The startup replay of stored
  predictions ran before any item was loaded, so it failed on the first one
  ("Could not restore model predictions") and the model review queue emptied
  on every restart. It now runs after the items load. It also applies the
  same checks as write-back: the leak guard, the confidence floor and
  reviewer rejections. It used to apply only the scheme check, and every
  prediction is stored, a run's training items included.
- **A text model trained on URLs.** Items with a `url`, `path` or
  `file_name` field gave the trainer that value instead of the text. A text
  vectorizer now always reads the text, and the model card records which
  input a model was fitted on.
- **Password resets failed under SSO.** With `method: oauth` and
  `allow_local_login`, the admin reset link, `/reset/<token>` and
  `potato reset-password` raised for every account. Local accounts can now
  be reset. For an SSO identity, the admin routes answer 409, no reset link
  is issued, and the CLI says the provider manages the password.
- **`ai_support` refused OpenRouter.** `endpoint_type: openrouter` (and
  `open_router`, as the docs show) is accepted.
- **CSS lengths with units.** `max_height: "50vh"` and similar became
  `50vhpx` in the text, PDF, code, spreadsheet, live agent and web agent
  displays. A unit is now kept; a bare number still means pixels. The web
  agent trace display raised on any string `screenshot_max_height`
  (`"600px"` included) and the page showed the item's text field instead.
- `labeling_engine.distill.image_field` must be a field name; a number used
  to validate.
- The embedding vectorizers declare scikit-learn tags, which scikit-learn
  1.8 will require.

## Documentation

The docs were reviewed against the code for the 2.9 to 2.11 releases. The
review corrected:

- wrong commands (`potato export`, the export CLI's flags);
- wrong URLs (the curation routes, `/go_to`);
- wrong defaults and response shapes;
- stale counts, which tests now check;
- keys documented in the wrong place;
- the debug `--host` requirement;
- the Hugging Face Spaces and backup pages, and SSO behaviour.

It also added notes that point older machine-labeling features to the
labeling engine.
