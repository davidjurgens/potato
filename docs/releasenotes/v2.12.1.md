# Release Notes: v2.12.1 — Display Logic, Export and Listening-Test Fixes

Fixes for bugs found in 2.12.0 after it was published, and two corrections
to its release notes.

```bash
pip install --upgrade potato-annotation
```

## Bug fixes

- **Unticking a checkbox updates display logic.** The page updated
  display logic when a box was ticked but not when one was unticked, so a
  question gated by `count_gt 1` stayed on screen after the boxes were
  cleared, and one gated by `count_equals 0` did not come back. This dates
  from before 2.12.0.
- **Survey-only studies export their answers.** With no item annotations,
  the CSV and TSV exports refused to run unless the study also used
  conditions, page rules, a runtime page or `trial_timing`, and JSONL always
  refused. With `export_include_phase_data: true` they now write the survey answers (CSV
  and TSV also write authenticity, participants and trials); without it, the
  error message names that key. JSONL no longer writes an empty
  `annotations.jsonl`.
- **Listening-test anchors need a WAV reference.** A `mushra` scheme with
  `anchors` and a FLAC or MP3 reference passed validation, and the anchor
  clips then returned HTTP 500. The server now refuses to start and names
  the item. `potato validate` does not load items, so it does not catch
  this, as with the other per-item listening-test checks.
- **The reliability export no longer logs a warning per resample.** On a
  small study, every bootstrap resample with no variation logged a
  `float division by zero` warning,
  about 300 lines at the default 1000 resamples on three items. The count is
  now given once, in the export's warnings and in `reliability.md`.
- **An MOT export that writes nothing fails.** When every sequence was
  skipped (a remote video whose size is unknown, say), the export reported
  success. It now fails with "Nothing was written." and the reasons.
- **`potato deploy --hf-oauth --dry-run` no longer warns that sign-in is
  open.** `--hf-oauth` replaces the sign-in page with Sign in with Hugging
  Face, and the preflight check `D003` now knows that.
- **The documentation site builds.** A link in the listening-tests page
  pointed at a page that had moved, which failed the strict docs build.

## Corrections to the 2.12.0 notes

- **`equals` on a multiselect.** The 2.12.0 notes said `equals` no longer
  matches a single selected option in the browser. It does, in the browser
  and on the server. What changed is that with two or more options ticked,
  `equals` is false in both; the browser used to compare the options'
  comma-joined text, so `equals: "a,b"` matched. Use `contains` to test
  whether an option is ticked.
- **Survey-only export.** The 2.12.0 notes said the CSV and TSV exports
  write phase answers for a study with no item annotations. In 2.12.0 that
  held only for studies that also used experiment-flow features; the first
  bug fix above makes it hold for any study with
  `export_include_phase_data: true`.
